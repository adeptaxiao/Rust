Для трекінгу використовується GitHub Issues.

## Bug #1 — Пошук без тегів повертає порожній результат без повідомлення

**Пріоритет:** Low  
**Статус:** Closed (виправлено)  
**Опис:** При виклику `filesindex get --tags ""` програма мовчки виводила "Файли не знайдено" замість того щоб повідомити що теги не задано.  
**Кроки відтворення:**
1. Запустити `filesindex get --tags ""`
2. Отримати порожній список без пояснення

**Виправлення:** Додано перевірку на порожній список тегів у `SqliteIndex::get` та `JsonIndex::get` — тепер функція одразу повертає `Ok(vec![])`. У бінарнику додано окреме повідомлення.

## Bug #2 — Паніка при некоректному форматі FILES_INDEX_PATH

**Пріоритет:** High  
**Статус:** Closed (виправлено)  
**Опис:** Якщо змінна середовища `FILES_INDEX_PATH` не містила символу `:`, програма панікувала з повідомленням `called Option::unwrap() on a None value`.  
**Кроки відтворення:**
1. `export FILES_INDEX_PATH=jsonindex`
2. Запустити будь-яку команду
3. Паніка

**Виправлення:** `split_once(':')` тепер обгорнуто в `.expect()` з зрозумілим повідомленням. У продакшн-версії варто повернути `Result` з `anyhow::bail!`.

---

## Bug #3 — Дублювання тегів при повторному add

**Пріоритет:** Medium  
**Статус:** Closed (виправлено)  
**Опис:** При повторному виклику `add` для того самого файлу з іншими тегами — старі теги не замінялися, а нові просто додавалися в JSON бекенді.  
**Кроки відтворення:**
1. `filesindex add --path a.txt --tags rust,code`
2. `filesindex add --path a.txt --tags docs`
3. `filesindex get --tags rust` — файл досі знаходиться

**Виправлення:** У `JsonIndex::add` змінено логіку: тепер теги повністю замінюються (не merge). У SQLite це вирішено через `INSERT OR REPLACE`.

# Порівняння багтрекінгових систем

| Система       | Переваги | Недоліки |
|---------------|----------|----------|
| **Jira** | Гнучкі воркфлоу, кастомні поля, потужні JQL-фільтри, підтримка Scrum/Kanban | Складний інтерфейс, повільний, дорогий для великих команд |
| **GitHub Issues** | Безкоштовний, тісна інтеграція з git/PR/Actions, простий інтерфейс | Обмежена кастомізація воркфлоу, базова система пріоритетів через labels |
| **Linear** | Швидкий сучасний UI, автотрекінг циклів, зручні гарячі клавіші | Менш гнучкий за Jira, новий продукт з меншою екосистемою |
| **Bugzilla** | Безкоштовний open-source, перевірений часом, детальна система компонентів | Застарілий інтерфейс, складне налаштування, слабка CI/CD інтеграція |

**Обраний інструмент:** GitHub Issues — як найпростіший варіант для навчального проєкту з прямою інтеграцією в репозиторій.
