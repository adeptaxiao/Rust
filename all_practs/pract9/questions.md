1. Для чого використовується крейт futures?

futures — це крейт що містить базові абстракції та утиліти для роботи з асинхронним кодом які не входять у std. Серед основних: трейти Stream та Sink, Future-комбінатори (then, map, and_then), методи для роботи з потоками задач (buffer_unordered, for_each_concurrent), синхронізаційні примітиви (oneshot, mpsc), а також try_join, select, join. Крейт існує бо std має лише сам трейт Future без екосистеми навколо. У цій роботі використовується stream::buffer_unordered для контролю паралелізму.

2. Які інструменти для роботи із асинхронним кодом є у tokio?

tokio::fs та tokio::io — асинхронні аналоги стандартного IO. tokio::net — TCP, UDP, Unix sockets. tokio::sync — Mutex, RwLock, Semaphore, Notify, канали (mpsc/broadcast/watch/oneshot). tokio::time — Sleep, Interval, timeout. tokio::task — spawn, spawn_blocking, JoinSet, JoinHandle. tokio::select! — макрос для очікування першого з кількох future. tokio::main та tokio::test — атрибути для запуску async функцій.

3. Чому погано використовувати синхронний Mutex між await викликами?

Синхронний Mutex блокує OS-потік. Якщо взяти його, потім зробити .await і задача призупиниться, guard залишиться захопленим. Worker-потік звільниться, але блокування тримається. Інша задача на тому ж worker може спробувати взяти той самий Mutex і заблокується. Якщо весь worker pool заблокується на одному Mutex поки задача-власник чекає на await — виникне deadlock. Для async контексту треба використовувати tokio::sync::Mutex.

4. Чому аргументи асинхронної задачі, яку ми "спавнимо", мають бути 'static?

tokio::spawn передає Future у виконавець який може запустити її на будь-якому worker-потоці і виконувати її будь-який час — навіть після того як функція що спавнила вже завершилася. Якщо аргументи містять не-'static посилання, вони можуть стати недійсними. Rust borrow checker не може перевірити час життя посилання через runtime у іншому потоці, тому єдина гарантія — 'static. Для передачі даних у спавнену задачу їх клонують (Arc::clone) або переміщають через move closure.
