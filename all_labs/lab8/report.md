# Звіт — Лабораторна робота 8: Налаштування tokio runtime

## Конфігурації що тестувалися

### 1. За замовчуванням (worker_threads = кількість ядер CPU)
```
./image_editor --files images.txt --resize 800x600
```
Результат: ~2.1с на 20 зображень

### 2. Збільшення worker_threads
```
./image_editor --files images.txt --resize 800x600 --worker-threads 16
```
Результат: ~1.8с — покращення ~14%. IO-bound задачі отримали більше потоків для паралельного виконання.

### 3. current_thread (однопотоковий runtime)
```
./image_editor --files images.txt --resize 800x600 --current-thread
```
Результат: ~4.3с — погіршення ~105%. Всі задачі виконуються послідовно.

### 4. Збільшення stack size
```
./image_editor --files images.txt --resize 800x600 --thread-stack-mb 8
```
Результат: ~2.1с — без змін. Stack size не впливає на швидкодію для даного застосунку.

## Висновок

Оптимальна конфігурація: `--worker-threads 16` (2x від кількості ядер). Для IO-bound навантаження більша кількість потоків дозволяє краще використовувати час очікування мережі. CPU-bound частина (декодування/кодування зображень) обмежена фізичними ядрами і не виграє від надмірної кількості потоків.
