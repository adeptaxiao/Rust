1. Що таке асинхронне виконання?

Асинхронне виконання — це модель де задачі можуть призупинятися у точках очікування (наприклад чекаючи відповідь від мережі) і повертати керування рантайму, який може запустити іншу задачу на тому ж потоці. Коли очікувана подія настає, задача продовжує виконання з місця призупинення. Це дозволяє одному потоку обробляти тисячі IO-bound операцій одночасно без створення тисяч системних потоків. У Rust асинхронність реалізована через async/await синтаксис, трейт Future та зовнішні рантайми (tokio, async-std).

2. Чому погано блокувати потік під час асинхронного виконання?

Асинхронні рантайми мають обмежену кількість worker-потоків. Коли задача блокує потік синхронним викликом (std::fs::read, std::thread::sleep), вона займає весь worker і не дає рантайму запускати інші задачі на ньому. Якщо всі worker-потоки заблоковані — весь рантайм зупиняється. Для блокувальних операцій треба використовувати tokio::task::spawn_blocking або асинхронні аналоги (tokio::fs, tokio::time::sleep).

3. Для чого існує трейт Future?

Future представляє значення яке буде доступне у майбутньому. Це абстракція над відкладеним обчисленням з єдиним методом poll, що повертає Poll::Pending або Poll::Ready(value). Усі async fn компілюються у структури що реалізують Future. Трейт дозволяє рантайму уніфіковано працювати з будь-якими асинхронними операціями та комбінувати їх через join, select тощо.

4. Чому існує Pin та Unpin в Rust?

Pin гарантує що значення не буде переміщене у памяті після закріплення. Це критично для self-referential структур — async fn компілюється у state machine яка може містити посилання на свої власні поля. Якщо таку структуру перемістити у памяті, посилання стане недійсним. Pin<&mut T> забороняє переміщення через safe API. Unpin — маркер що означає "переміщення цього типу безпечне навіть з-під Pin". Більшість простих типів автоматично Unpin; Future створені async fn зазвичай ні.
