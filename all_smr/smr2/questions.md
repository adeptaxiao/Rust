# Самостійна робота 2
## Тема: Забезпечення коректності та стабільності ПЗ: документація та публікація крейтів.

---

## 1. Локальна документація та кешування залежностей

### Локальна документація

Rust дозволяє згенерувати документацію для проєкту та всіх його залежностей локально командою:

```bash
cargo doc --open
```

Прапор `--open` автоматично відкриває документацію у браузері. Документація генерується у директорію `target/doc/`. Для включення документації залежностей (без прапора `--no-deps`):

```bash
cargo doc --open  # генерує doc для крейту та залежностей
```

Якщо потрібна документація лише для приватних елементів:

```bash
cargo doc --document-private-items
```

Документація зберігається локально і доступна без інтернету після першої генерації.

### Кешування залежностей

**Cargo registry cache** — при завантаженні крейту Cargo зберігає його у `~/.cargo/registry/`. Структура:

```
~/.cargo/registry/
  cache/        — .crate архіви (стиснуті вихідники)
  src/          — розпаковані вихідники
  index/        — індекс реєстру (метадані)
```

Після першого завантаження крейти не завантажуються повторно навіть без інтернету.

**`cargo vendor`** — копіює всі залежності у локальну директорію `vendor/` всередині проєкту:

```bash
cargo vendor
```

Після цього у `.cargo/config.toml` додається:

```toml
[source.crates-io]
replace-with = "vendored-sources"

[source.vendored-sources]
directory = "vendor"
```

Тепер `cargo build` не потребує інтернету взагалі — всі крейти беруться з `vendor/`.

**`cargo fetch`** — завантажує всі залежності у кеш без компіляції:

```bash
cargo fetch
```

Зручно для підготовки до роботи офлайн.

**Локальний реєстр (`cargo local-registry`)** — крейт `cargo-local-registry` дозволяє створити локальний реєстр із `.crate` файлів для використання в ізольованих середовищах.

## 2. Документування Rust проєктів

### Doc-коментарі

Rust підтримує два види документаційних коментарів:

`///` — документує наступний елемент (функцію, структуру, модуль):

```rust
/// Обчислює суму двох чисел.
///
/// # Examples
///
/// ```
/// let result = add(2, 3);
/// assert_eq!(result, 5);
/// ```
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}
```

`//!` — документує поточний елемент (зазвичай файл або модуль):

```rust
//! Бібліотека для роботи з матрицями.
//!
//! Надає ефективні операції над двовимірними масивами.
```

### Синтаксис документації

Документація пишеться у форматі **Markdown**. Підтримуються стандартні секції:

- `# Examples` — приклади коду (автоматично запускаються як тести через `cargo test`)
- `# Errors` — опис помилок що повертає функція
- `# Panics` — умови при яких функція панікує
- `# Safety` — для `unsafe` функцій — пояснення інваріантів
- `# Arguments` — опис аргументів (альтернативно можна описувати inline)

### Doc-тести

Код у блоках ` ```rust ` в документації автоматично компілюється і виконується при `cargo test`. Це гарантує що приклади завжди актуальні:

```bash
cargo test --doc
```

Якщо приклад не повинен компілюватися (наприклад, демонстрація помилки):

```rust
/// ```compile_fail
/// let x: i32 = "hello"; // не компілюється
/// ```
```

### Посилання у документації

```rust
/// Повертає [`String`] або [`Option<String>`].
/// Дивись також [`super::other_module`].
pub fn example() -> String { ... }
```

### Атрибути документації

`#[doc(hidden)]` — приховує елемент з документації але залишає його публічним.
`#[doc = "..."]` — програмне додавання документації.

## 3. Публікація крейтів на crates.io

### Підготовка до публікації

Мінімальний `Cargo.toml` для публікації:

```toml
[package]
name = "my-crate"
version = "0.1.0"
edition = "2021"
description = "Короткий опис крейту"
license = "MIT OR Apache-2.0"
repository = "https://github.com/user/my-crate"
```

**Обов'язкові поля:** `name`, `version`, `edition`.

**Рекомендовані:** `description`, `license`, `repository`, `readme`, `keywords` (до 5), `categories`.

### Обмеження та вимоги

- Ім'я крейту унікальне в межах crates.io і не може бути змінене після публікації
- Версія повинна відповідати Semantic Versioning (SemVer)
- Опублікований крейт не можна видалити (тільки yanked — позначити як небажаний)
- Максимальний розмір крейту — 10 МБ
- Файли з `Cargo.toml` поля `exclude` не потраплять до архіву
- Потрібен акаунт на crates.io та API токен

### Процес публікації

```bash
cargo login <API_TOKEN>   # авторизація
cargo publish --dry-run   # перевірка без публікації
cargo publish             # публікація
```

### Yanking

Якщо у версії виявлено критичну помилку — її можна "відкликати":

```bash
cargo yank --vers 0.1.0
```

Yanked версія залишається доступною для проєктів що вже її використовують (через `Cargo.lock`), але нові проєкти не зможуть її додати як залежність.

### Власні реєстри крейтів

Для приватного використання (корпоративна розробка) можна розгорнути власний реєстр. Варіанти:

**`cargo-registry` / `meuse`** — open-source реалізації приватного реєстру.

**Gitea/Forgejo** — підтримують вбудований Cargo реєстр з версії 1.20.

**`kellnr`** — спеціалізований приватний Cargo реєстр з веб-інтерфейсом.

Конфігурація у `~/.cargo/config.toml`:

```toml
[registries.my-company]
index = "https://registry.company.com/index"
token = "secret-token"
```

Публікація у приватний реєстр:

```bash
cargo publish --registry my-company
```

Залежність з приватного реєстру:

```toml
[dependencies]
internal-crate = { version = "1.0", registry = "my-company" }
```
